● "Save to notes" and "Record a decision" are the same feature underneath. The
  spec calls it the decision journal (FINN_BUILD_SPEC.md §9.3). Both buttons
  write to one database table.

  Where it's stored

  There's one table called decision (backend/app/models.py:230). It lives in the
  app's main database: Postgres on the deployed app, SQLite when you run it
  locally.

  ┌────────────┬─────────────────────────────────────────────┐
  │   Column   │                What it holds                │
  ├────────────┼─────────────────────────────────────────────┤
  │ company_id │ The stock it's about (always required)      │
  ├────────────┼─────────────────────────────────────────────┤
  │ event_id   │ The event it was made on, if any (optional) │
  ├────────────┼─────────────────────────────────────────────┤
  │ action     │ One of hold, add, trim, exit, note          │
  ├────────────┼─────────────────────────────────────────────┤
  │ note       │ Your one-line reason, cut to 500 characters │
  ├────────────┼─────────────────────────────────────────────┤
  │ created_at │ When you saved it                           │
  └────────────┴─────────────────────────────────────────────┘

  Notes are stored on the server, not in the browser, so they survive a refresh
  and show up on any device.

  How each button saves

  Both buttons send a POST /api/decisions request
  (backend/app/api/decisions.py:32):

  - Record a decision (frontend/components/decide-sheet.tsx): you pick Hold,
    Add, Trim, Exit or Note and type or dictate a reason. It's sent with the
    company symbol and the event id.
  - Save to notes in Ask (frontend/components/ask-sheet.tsx:107): saves with
    action: "note". The note text is "Asked: <your question> Answer: <answer>".
    The [1]-style citation markers are removed and the answer is cut to 380
    characters.

  The backend checks that the action is one of the five allowed values. It works
  out the company from the symbol, or from the event if no symbol was sent. If
  it can find neither, it rejects the request.

  Why: where your notes show up again

  The point is to remind you what you thought last time, so you don't react to
  each new event from scratch.

  1. "Last time you…" on event cards in the brief
     (backend/app/push/digest.py:99). When a new event comes in for a company,
     the card shows your latest decision on that company, for example "Last time
     (14/06) you chose hold: 'watch for more exits'". Your note isn't shown if
     it was made on that same event, or if it's more than 60 days older than the
     event.
  2. Event page: shows "On <date> you chose …" from before this event
     (api/common.py:43). It also has a "Your decisions on this" list of
     everything you saved on that event.
  3. Company page: a "Your decisions" section with the 20 newest, newest first
     (api/companies.py:57).
  4. GET /api/decisions: lists all of them, and can be filtered by symbol.

  One limitation: there's no edit or delete endpoint, so once a note is saved it
  stays. If you want, I can add delete.

● I read the design doc (FINN_DESIGN_SYSTEM.md) and the Brief page code. I
  haven't looked at screenshots of the running app, so these are ideas, not an
  audit of what's on screen. I've changed nothing.

  The app already avoids the usual AI tells: ledger rows instead of cards, serif
  quotes on the highlighter, sentence case, no gradients. What makes something
  look AI-built now is less about decoration and more about whether the screens
  show a real point of view. Most of these ideas push the "marked-up filing"
  idea further, so the app feels like an analyst's own working copy.

  Signature ideas (highest impact)

  1. Red-pen corrections for results. When a number misses guidance or changes
  from last quarter, show it like an editor's correction: the old or guided
  value struck through in ink-3, the actual value next to it in down or up. For
  example: 24–25% 21.8%. It says "this changed" in a way only FINN would. It
  uses only existing tokens.

  2. Your decisions as margin notes. Right now "Last time you chose hold…" is a
  line of text inside the row. Put it in the 48px margin column, like a pencil
  note: a short ink-2 italic line with a thin rule. When you save a decision, a
  small stamp ("Held, 15 Nov") appears in that row's margin. The journal then
  looks like your handwriting on the ledger.

  3. Tick off rows you've read. After you open an event, show a small ink check
  in its margin and dim the title to ink-2. That's how people work through a
  printed list, and you get a "you've read 2 of 3" feeling without adding a
  progress bar.

  4. Footnotes, not citation chips, in Ask. Show citations as superscript
  numbers (¹ ²) with a footnote list under the answer: "¹ Q2 FY27 concall, p.
  4". Tapping one opens the source sheet with that line highlighted. This looks
  like a research note, not a chatbot.

  5. Company timeline strip. A dense ruled line across the top of the company
  page with tick marks for results, key staff exits, promises and your
  decisions. "Second key exit in five months" then shows up as a visible
  pattern, not only a sentence.

  Making it denser

  - Brief header: add the benchmark next to the hero number ("−0.82% vs Nifty
    −0.31%"). The gap between them is the number investors actually care about.
  - Portfolio rows: a tiny 30-day line chart in ink at low opacity, with no
    axes. It only shows shape, at almost no cost in space.
  - Event detail: put the three key numbers (weight, move, ₹ impact) in one
    ruled row at the top before any text, so the size of the problem comes
    first.
  - Promise ledger: show the score as a row of marks (✓ ✗ ✓ – ✓), where each one
    opens that promise. It's more tactile than a segmented bar.

  Copy and states that show someone thought about it

  - Empty states with real facts: "Nothing needs you today. The last urgent item
    was the Kestrel CFO exit, 9 days ago." That's better than a generic "all
    clear".
  - Weekend awareness: "Sunday, markets closed. Prices are Friday's close." The
    cron jobs now run on weekends, so the screen should say it.
  - Real progress in Research: "Reading FY25 annual report, page 42 of 188"
    instead of a spinner. Show the actual document names as they get done.
  - Honest misses in Ask: "The filings don't say this. Closest: …", with a
    quote. Saying what it doesn't know is the opposite of slop.
  - Error lines that name the source and time: keep the style already in the
    design doc ("Couldn't reach NSE. Showing filings checked at 08:10") on every
    screen, including Alerts and Research.

  Things to check and possibly cut

  - Counts in brackets on every heading: keep them where the number matters
    ("Needs you today (3)"). Drop them where it's noise.
  - Skeletons: if every screen uses the same 8 grey lines, make each one match
    its screen's real layout (margin column plus two lines). Identical skeletons
    are a template tell.
  - Too many blue links in one row: if a row has 3 or more blue links, keep one
    and turn the rest into ordinary text.
  - Freshness footer: "Never real-time." sounds defensive. "Prices are end of
    day." says the same thing calmly.
  - The test in section 9 of the design doc: cover the logo and ask whether
    you'd still know it's FINN. If only the highlighter gives it away, ideas 1–3
    add a second and third signature.

  If you only do three

  Do red-pen corrections (1), margin notes for decisions (2) and footnote
  citations in Ask (4). Each needs no new colours or fonts, and each strengthens
  the "marked-up filing" idea that sets FINN apart.
